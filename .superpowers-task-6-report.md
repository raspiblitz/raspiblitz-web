# Task 6 report — SSE → WebSocket migration for realtime hook

## Status: DONE

## Summary

Replaced the browser `EventSource` connection in `src/hooks/use-realtime.tsx`
with a `WebSocket` that:

- Sends `{"type":"auth","token":<ACCESS_TOKEN from localStorage>}` as the
  first message once the socket opens.
- Dispatches incoming `{"event":<name>,"data":<payload>}` frames to the 12
  existing (unmodified) handler functions via a `DISPATCH` map, wrapping the
  payload back into a `MessageEvent<string>`-shaped object so the handler
  bodies did not need to change.
- Reconnects with exponential backoff (1s → doubling, capped at 30s) on any
  non-4401 close.
- Calls `AppContext.logout()` when the socket closes with code 4401.

## A deviation from the literal spec, and why

The spec's example `connect()`/effect code calls `setSocket(ws)`
unconditionally, and its effect dependency array included `sseCtx`/`appCtx`.
Implementing it exactly that way produced an infinite reconnect loop and
crashed the test worker with an OOM (`heap out of memory`): `sseCtx`/`appCtx`
are new object identities on every render of their respective providers, so
every `setSocket` call (which triggers a re-render) changed `sseCtx`'s
identity, which re-ran the effect (since `sseCtx` was a dep), which called
`connect()` again, which called `setSocket` again — forever.

Fix: the effect's dependency array now only contains `[t, setSocket,
appInstallSuccessHandler, appInstallErrorHandler]` (all stable across
re-renders), so the socket effect truly runs once on mount and tears down on
unmount, matching the intent described in the task ("the effect should set
up the socket once on mount and tear down on unmount"). The handler bodies
still reference `sseCtx.setXxx(...)` directly from closure — safe, since
React guarantees `useState` setters are stable forever regardless of which
render's `sseCtx` snapshot captured them. For `appCtx.logout()` (used only in
the 4401 branch), added a `appCtxRef` ref that's kept up to date via a small
separate effect (`useEffect(() => { appCtxRef.current = appCtx }, [appCtx])`),
so the socket effect always calls the *latest* `logout` implementation
without needing `appCtx`'s unstable identity in its own dependency array.
